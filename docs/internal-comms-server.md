# خادم «وصل» وقاعدة بياناته

## البنية

تُحفظ بيانات النظام في Supabase Postgres داخل مخطط خاص اسمه `wasl`. المخطط غير مكشوف في واجهة Supabase العامة، وكل جداوله تفرض سياسات أمان الصفوف، ولا صلاحية عليها لدوري `anon` و`authenticated`. يتصل الخادم وحده بقاعدة البيانات عبر `lib/server/db.ts`، ولا يتصل المتصفح بها مباشرة.

- `lib/server/auth.ts`: الجلسات الموقعة، والدخول، والحسابات.
- `lib/server/ops.ts`: كل عمليات التعديل عبر `POST /api/ops`. تعيد كل عملية تنفيذ قواعد `lib/media-workflow.ts` على الخادم بتوقيته، داخل معاملة واحدة مع قفل صف الفكرة.
- `lib/server/state.ts`: ما يراه كل مستخدم. عروض الأسعار وملفاتها لصاحب الفكرة ومدير الإدارة ومدير النظام فقط، وكل عضو يستلم إشعاراته وحده.
- `lib/server/files.ts`: رفع المرفقات وتنزيلها. يُربط كل ملف مرفوع بالفكرة التي رُفع لها، ولا يمكن إلحاقه بفكرة أخرى.
- `lib/server/repository.ts`: التحويل بين صفوف الجداول وأشكال البيانات في الواجهة.

المرفقات محفوظة حالياً على قرص الخادم في `MEDIA_DATA_DIR/files` (أو `.media-data/files`). تنتقل إلى Google Drive في المرحلة P2 من خطة الإصلاح.

## الإعداد

ضع القيم التالية في `.env.local` على الخادم فقط:

| المتغير | الغرض |
|---|---|
| `SUPABASE_URL` | عنوان مشروع Supabase |
| `SUPABASE_DB_PASSWORD` | كلمة مرور قاعدة البيانات كما هي |
| `WASL_SESSION_SECRET` | مفتاح عشوائي لتوقيع الجلسات، 32 حرفاً على الأقل |
| `MEDIA_APP_ORIGIN` | اختياري: عنوان النظام العام خلف وسيط عكسي |
| `MEDIA_DATA_DIR` | اختياري: مسار كامل لحفظ المرفقات |

## أوامر قاعدة البيانات

```sh
npm run db -- check
npm run db -- migrate
npm run db -- import-state --server-stopped
npm run db -- verify-state
```

- `check` يختبر الاتصال.
- `migrate` يطبّق ملفات `supabase/migrations` غير المطبقة، ويسجلها في `supabase_migrations.schema_migrations`.
- `import-state` ينقل ملف `state.json` القديم في معاملة واحدة، ولا يكرر شيئاً إذا أُعيد. يضع وسم «تجريبية» على أفكار العينة، ويعامل الإشعارات القديمة كأنها أُرسلت بالبريد.
- `verify-state` يقارن الأعداد بين الملف القديم وقاعدة البيانات.

## الدخول

- الجلسة صالحة 12 ساعة، في ملف تعريف ارتباط HttpOnly بإعداد SameSite=Strict. تبطل كل جلسات العضو عند تغيير اسمه أو مسماه أو صلاحيته أو حالته أو اسم دخوله أو كلمة مروره.
- كلمات المرور الجديدة 12 حرفاً على الأقل لمديري النظام و10 لغيرهم، وتُرفض الكلمات السهلة.
- المحاولات الخاطئة تبطئ الدخول من الجهاز نفسه بفترات متزايدة حتى 15 دقيقة، ولا تقفل صاحب الحساب إذا دخل من جهاز آخر.
- حساب root محمي: لا يعدّله إلا صاحبه، ولا يُعطَّل، ولا تتغير صلاحيته.

## واجهات الخادم

- `GET /api/session` يعيد `{user,demo:false,configured:true}`. `POST` يسجّل الدخول بـ `{username,password}`، و`DELETE` يسجّل الخروج.
- `GET /api/media` يعيد بيانات المستخدم الحالي بعد التصفية حسب دوره.
- `POST /api/ops` ينفّذ عملية واحدة، مثل `{type:"addComment",ideaId,text}`. يعيد الفكرة بعد التعديل وإشعارات المستخدم.
- `GET/POST /api/accounts` لإدارة الحسابات، ومتاح لمديري النظام فقط.
- `POST /api/files` يرفع المرفقات. `GET /api/files/:id` ينزّلها بعد التحقق من الصلاحية.
- `GET/POST /api/drive` يعيد «غير مربوط» حتى اكتمال ربط Google Drive في المرحلة P2.

## الاختبارات

`npm run verify` يشغّل فحص الأنواع، والـ lint، واختبارات سير العمل والمخزن والخادم وقاعدة البيانات، ثم البناء. اختبارات الخادم وقاعدة البيانات تعمل على Postgres داخل الذاكرة (PGlite)، فلا تلمس بيانات Supabase.
