# وصْل — مساحة فريق التواصل الداخلي

نظام عربي لإدارة العمل بين فريق المحتوى والتنسيق، مدير الإدارة، وفريق التصميم. يجمع الفكرة والنص وخطة التنفيذ وعروض الأسعار والاعتماد والجدولة والمخرجات النهائية في سجل واحد قابل للبحث.

## إمكانات الفريق

- أفكار مرتبطة بالشركة وإدارة الطلب والتصنيف وقنوات النشر، مع مرفقات متعددة وحفظ مقدم المقترح ونصه الأصلي.
- مراجعة المدير، وملاحظات واضحة، وتعديل الفكرة وإعادة إرسالها، ثم ترحيل الأفكار المعتمدة إلى التصميم.
- جدولة التنفيذ وتسليم المخرجات لكل قناة: الشاشات 16:9، واتساب 9:16، والبريد الداخلي.
- دردشة جماعية، ونقاشات مرتبطة بالأفكار والأعمال والشركات والتصنيفات ولوحة العمل، مع ردود وإشارات لأعضاء الفريق وتفاعلات وتثبيت الرسائل.
- إشعارات فورية بإسناد الأعمال، وبكل إجراء للفريق إلى مدير الإدارة، تتضمن صاحب الإجراء وصورته الرمزية. يفتح الإشعار العمل أو الرسالة المعنية مباشرة.
- تهنئة بالإنجاز، وبطاقات خضراء للأعمال المكتملة، مع حركة احتفالية قصيرة تراعي تفضيل تقليل الحركة.
- تسجيل صوتي يُراجع قبل الإرسال، بحد أقصى دقيقتين و1 ميجابايت. يستهدف المتصفح قناة واحدة و16 كيلوبت/ثانية باستخدام Opus؛ يدعم AAC عند الحاجة. يتحقق الخادم من الملف والمدة الفعلية، ويحمي الاستماع بصلاحيات الجلسة.
- تحرير مركزي للأعمال وإسنادها، وسلة محذوفات قابلة للاستعادة تحفظ الملفات والسجل، وإضافة الشركات والتصنيفات وإيقافها وإعادة تفعيلها.
- إدارة الأعضاء وأسماء الدخول والصلاحيات وكلمات المرور من لوحة الإدارة، مع حساب مالك النظام المحمي `root`.
- عرض اعتماد PowerPoint وحزمة ZIP للمرفقات، وتقرير شهري عمودي A4، وتصدير Excel وCSV محسوب بتوقيت الرياض.
- ربط Google Drive عبر OAuth، وأرشفة تلقائية للملفات النهائية، واستكمال رفع الملفات الكبيرة، ونسخ احتياطية مشفرة.

## التشغيل

يحتاج النظام إلى إعداد قاعدة بيانات Supabase Postgres ومفاتيح الجلسات والتشفير على الخادم. اتبع [دليل إعداد الخادم](docs/internal-comms-server.md)، ثم:

```sh
npm ci
npm run db -- check
npm run db -- migrate
npm run dev
```

افتح [التطبيق المحلي](http://localhost:3000). يحفظ النظام البيانات في مخطط Postgres خاص اسمه `wasl`، والمرفقات في تخزين خاص وفق إعدادات الخادم. لا تُعرض كلمات المرور أو مفاتيح الخادم في المتصفح. التحقق بخطوتين مطلوب افتراضياً لمديري النظام في نسخة الإنتاج.

```sh
npm run build
npm run start
```

## التحقق

```sh
npm run verify
```

يشمل التحقق الأنواع، وlint، وسير العمل والصلاحيات والجلسات والمرفقات والاستيراد وGoogle Drive وقاعدة البيانات والدردشة والرسائل الصوتية والإشعارات، ثم البناء. تعمل الاختبارات على قواعد ومجلدات وواجهات Google معزولة، ولا تغيّر بيانات العمل أو ترسل رسائل بريد حقيقية.

توجد أوامر `test:social` و`test:activity` لتشغيل اختبارات الميزات الاجتماعية وأحداث الفريق وحدها. بيئة اختبارات الواجهة المحلية موثقة في `playwright.config.ts` و`e2e/seed.cjs`، وتستخدم قاعدة منفصلة على المنفذ 54329.

## البنية والمراجع

يستخدم التطبيق Next.js App Router وReact وTailwind CSS، بواجهة عربية من اليمين إلى اليسار. توجد الواجهات في `components/media/`، وقواعد العمل في `lib/media-workflow.ts`، وخدمات الخادم في `lib/server/`، وترقيات قاعدة البيانات في `supabase/migrations/`.

تستخدم الدردشة واجهات `app/api/social/`. ترسل `GET /api/events` مؤشرات التغيير عبر SSE؛ يعيد المتصفح قراءة البيانات من الواجهات المحمية، مع تحديث دوري عند انقطاع الاتصال. تُراجع صلاحية الجلسة أثناء الاتصال، ولا تُرسل بيانات الأعمال أو الحسابات داخل قناة الأحداث نفسها.
